# Словарь терминов курса «Защита ОС Linux»

Назначение: единые канонические формы терминов для всех лекций курса. Правила пользования:

1. **Первое употребление** — полная русская форма с английским эквивалентом или аббревиатурой в скобках: «идентификатор пользователя (UID)», далее — одна выбранная форма без чередования синонимов.
2. **Нормативные определения** цитировать дословно в «кавычках» с указанием источника и пункта в форме «ГОСТ Р 58833-2020, п. 3.24»; пересказ своими словами не оформлять как цитату.
3. **Идентификаторы** (номера стандартов, пункты, CVE, форматы хешей вида `$y$`, версии) не изменять без проверки по первоисточнику.
4. Словарь — живой: устоявшийся в новой лекции термин дописывать в соответствующий раздел.

## Нормативные определения (цитировать дословно)

| Термин | EN | Источник | Определение |
|---|---|---|---|
| Субъект доступа | subject | РД Гостехкомиссии, 1992, п. 6 | «Лицо или процесс, действия которого регламентируются правилами разграничения доступа» |
| Объект доступа | object | РД Гостехкомиссии, 1992, п. 7 | «Единица информационного ресурса автоматизированной системы, доступ к которой регламентируется правилами разграничения доступа» |
| Идентификация | identification | ГОСТ Р 58833-2020, п. 3.24 | «Действия по присвоению субъектам и объектам доступа идентификаторов и/или по сравнению предъявляемого идентификатора с перечнем присвоенных идентификаторов» |
| Аутентификация | authentication | ГОСТ Р 58833-2020, п. 3.4 | «Действия по проверке подлинности субъекта доступа и/или объекта доступа, а также по проверке принадлежности субъекту/объекту доступа предъявленного идентификатора и аутентификационной информации» |

При сопоставлении отечественных и зарубежных требований называть документы парой:
методический документ ФСТЭК «Меры защиты информации в ГИС» (меры ИАФ) ↔ NIST SP 800-63B-4 (2024).
Подходы различать по существу, не оценочно: ФСТЭК формализует состав и смену пароля,
NIST делает ставку на длину.

## Управление доступом

| Термин | EN / аббр. | Употребление |
|---|---|---|
| разграничение доступа | access control | канонический термин курса; не чередовать с «контроль доступа» |
| правила разграничения доступа | access control rules | по РД 1992; аббревиатуру ПРД вводить только при повторном частом употреблении |
| авторизация | authorization | решение «разрешён ли доступ»; раскрывается в лекции 3 |
| монитор обращений | reference monitor | Андерсон, 1972; TCSEC; в профиле защиты ОС ФСТЭК — функция безопасности FPT_MTR_EXT.1 |
| политика безопасности | security policy | — |
| привилегия, привилегированный процесс | privilege, privileged process | «привилегированный» = действующий с полномочиями суперпользователя, если не оговорено иное |
| дискреционное управление доступом | DAC, discretionary access control | ожидается в последующих лекциях; на первом употреблении — полная форма + аббревиатура |
| мандатное управление доступом | MAC, mandatory access control | то же |
| модель угроз | threat model | обязательна при оценочных утверждениях о защищённости |
| поверхность атаки | attack surface | — |

## Учётные записи и группы

| Термин | EN / аббр. | Употребление |
|---|---|---|
| учётная запись | account | не «учётка», не «аккаунт» |
| идентификатор пользователя | UID, user identifier | первое употребление — полная форма, далее UID |
| идентификатор группы | GID, group identifier | аналогично |
| суперпользователь | superuser, root | «root» допустим как имя учётной записи; «рутовый» недопустимо |
| псевдопользователь | pseudo-user, system account | служебная учётная запись без интерактивного входа; термин курса, вводить с определением |
| первичная группа | primary group | задаётся полем GID в /etc/passwd, а не в /etc/group |
| вторичные группы | supplementary groups | в man-страницах — supplementary; «дополнительные» не чередовать с «вторичные» внутри одной лекции |
| «запрещающая» оболочка | — | метафора курса для nologin, /bin/false; всегда в кавычках |

## Идентификаторы процесса

| Термин | EN / аббр. | Употребление |
|---|---|---|
| реальный UID | real UID, ruid | кто запустил процесс |
| эффективный UID | effective UID, euid | используется при проверке прав доступа |
| сохранённый UID | saved set-user-ID | писать полностью «сохранённый UID»; не сокращать до «suid» — коллизия с setuid-битом |
| setuid-бит | set-user-ID bit | через дефис, латиницей; «при запуске дать процессу euid владельца файла» |
| сброс привилегий | privilege drop | необратимый — setuid(2); обратимый — seteuid(2) |
| «качели привилегий» | — | метафора курса для чередования seteuid; в кавычках, преимущественно в заметках докладчика |
| наследование идентификаторов | — | правила fork(2)/execve(2); системные вызовы оформлять как `<Man>`-ссылки |

## Пароли и парольная аутентификация

| Термин | EN / аббр. | Употребление |
|---|---|---|
| односторонняя функция | one-way function | принятая в курсе форма; не чередовать с «однонаправленная» |
| хеш пароля | password hash | форматы (`$y$` yescrypt, `$gy$` gost-yescrypt и др.) воспроизводить точно |
| соль | salt | без кавычек; при первом употреблении кратко определить назначение |
| перебор по словарю | dictionary attack | атака Морриса 1988 г. — опорный исторический пример курса |
| многофакторная аутентификация | multi-factor authentication, MFA | раскрывается в лекции о PAM |
| PAM | Pluggable Authentication Modules | при первом употреблении раскрыть аббревиатуру; содержательно — лекция 3 |

## Недопустимые разговорные замены

| Недопустимо | Писать |
|---|---|
| юзер | пользователь |
| учётка, аккаунт | учётная запись |
| админ | администратор |
| залогиниться, разлогиниться | выполнить вход в систему, завершить сеанс |
| права (без уточнения) | права доступа |
| рутовый, под рутом | с привилегиями суперпользователя |
| пароль «взломан» | пароль подобран / скомпрометирован |
| «безопасный дистрибутив», «Linux безопасен» | указать механизм защиты и модель угроз, в рамках которых справедливо утверждение |

# Захваченные выводы (captures)

Курируемые транскрипты терминальных сессий для слайдов лекции; показываются
компонентом `TerminalCapture` (секции разделены строками `===== Заголовок =====`).

Нумерация продолжает каталог демо лекции 2 (`…_old/assets/demos/01-13`); файлы
14–15 — не сценарии, а транскрипты, снятые 19.10.2026 в одноразовом контейнере
`ubuntu:26.04` (Ubuntu 26.04.1 LTS). Пользователи: `bob` (группы `bob`, `project`),
`alice` (`alice`, `adm`, `project`), `carol` (только `carol`); группа `project` —
GID 1010. Табуляция развёрнута (`expand -t 8`), иначе колонки TCallout съезжают.

- `14-object-types.txt` — сеанс пользователя `bob`, одна секция: типы объектов
  с файловым интерфейсом (`-`, `d`, `c`, `p`, `s`) и процесс в `/proc`.
- `15-identification-basics.txt` — корневой сеанс: `id`, `groups`, строки
  `/etc/group` и `/etc/passwd` для пользователей с разным членством в группах.
- `16-etc-passwd.txt` — корневой сеанс: полный `cat /etc/passwd` (в контейнере
  дополнительно установлен `openssh-server`, поэтому есть псевдопользователи
  `sshd`, `systemd-*`, `messagebus`), пример поля 2 и права доступа
  (`stat` для `/etc/passwd` и `/etc/shadow`).
- `01-passwd-uid-zero.txt` — перенесён из старой лекции (демо 01: подмена UID
  в третьем поле) и переразбит на две секции под слайд: «до» (строка + `id`)
  и «после» (sed + строка + `id`); команды и вывод не менялись. Снят отдельным
  сценарием (`…_old/assets/demos/01-passwd-uid-zero.sh`), поэтому `alice` там
  имеет UID 1001.
- `02-group-membership.txt` — перенесён из старой лекции (демо 02: членство
  в группах); секции переразбиты под слайд: `id` и оба `grep` сведены в одну
  секцию, команды и вывод не менялись. Снят отдельным сценарием
  (`…_old/assets/demos/02-group-membership.sh`), поэтому `bob` (UID 1001) там —
  член групп `adm`, `sudo`, `users`.

- `03-process-credentials.txt` — перенесён из старой лекции (демо 12:
  идентификаторы процесса в `/proc` и setuid-бит `passwd`) и переразбит на три
  секции под слайды: оболочка root, процесс `bob`, setuid-программа `passwd`;
  пояснительные строки-ремарки убраны, команды и вывод не менялись. Снят
  сценарием `…_old/assets/demos/12-process-credentials.sh` (в новой нумерации
  демо 03).
- `04-uid-inheritance.txt` — перенесён из старой лекции (демо 13: наследование
  идентификаторов при `fork`/`execve`, setuid-утилита `idprobe`); секции те же,
  финальная строка-ремарка убрана. Снят сценарием
  `…_old/assets/demos/13-uid-inheritance.sh` (в новой нумерации демо 04).
  Секция «Сброс привилегий: seteuid(2) против setuid(2)» дозаписана 19.10.2026
  в одноразовом контейнере `ubuntu:26.04` (bob — UID 1001, `idprobe` в режиме
  `drop` собран статически с хоста, setuid root): качели seteuid(ruid)/seteuid(suid)
  с функциональной проверкой — попыткой открыть `/etc/shadow` — и окончательный
  сброс setuid(ruid) с отказом setuid(0); повторяет эксперименты exp_3/exp_4
  из учебного примера `.sources/misc/03_resids_output_ids.c`.

- `17-etc-shadow.txt` — транскрипт, снятый 26.10.2026 в одноразовом контейнере
  `ubuntu:26.04` (Ubuntu 26.04.1 LTS, установлены `openssh-server`, `whois`,
  `util-linux-extra`; пользователи как в 15/16: `bob` 1001 (+`project`),
  `carol` 1002, `alice` 1003 (+`adm`, `project`), группа `project` — GID 1010;
  у `bob` и `alice` задан одинаковый пароль, у `carol` пароль не задан).
  Секции: полный `cat /etc/shadow`, выборка строк `/etc/gshadow`, права
  доступа (сеанс `bob`: `ls -l`, отказ `cat`, setuid/setgid-утилиты).
- `05-password-hashing.txt` — демо 05 (тот же контейнер, корневой сеанс):
  воспроизведение хеша `bob` командой `mkpasswd` с солью из `/etc/shadow`
  (верный/неверный пароль), `sha256sum` без соли, случайная соль
  (одинаковый пароль `bob`/`alice` — разные хеши), фиксированная соль.
  Пароль примера публичный: `Lab-Demo-42!`. Сценарий —
  `demos/05-password-hashing.sh` (там временные пользователи `ossec-demo*`).
  Курирование: в секциях 1 и 3 между блоками команд вставлены пустые строки,
  чтобы номерные выноски TCallout соседних строк не накладывались.
- `06-password-policy.txt` — демо 06 (тот же контейнер): поля устаревания
  до и после `chage -m 1 -M 90 -W 7 -I 14 -E 2027-12-31`, значения по
  умолчанию из `login.defs`, блокировка `passwd -l alice` с попыткой `su`
  с верным паролем, пустое поле хеша (`passwd -d carol`, `su` без запроса
  пароля — в `common-auth` Ubuntu у `pam_unix` включён `nullok`), пароль
  группы в `/etc/gshadow` (`newgrp`: член `project` без пароля; не-член
  `bob` входит в `audit` по паролю группы `Audit-Demo-7!`, заданному через
  `chgpasswd`; `carol` без пароля — отказ). Сценарий —
  `demos/06-password-policy.sh`. День 20752 = 26.10.2026, 21183 = 31.12.2027.
  Курирование: длинные yescrypt-хеши в секциях 1, 2 и 6 сокращены
  многоточием `…` (одна ячейка), чтобы строки помещались без прокрутки;
  секция 6 дозаписана 26.10.2026 в свежем контейнере `ubuntu:26.04`
  (группа `audit` GID 1011 без членов, пароль задан `chgpasswd`;
  `newgrp` — из пакета `util-linux-extra`).

- `07-user-defaults.txt` — демо 07 (раздел 4; тот же образ `ubuntu:26.04`, корневой
  сеанс, 29.10.2026, день 20755). Секции: `useradd -D` (умолчания
  `/etc/default/useradd`, в т. ч. `SHELL=/bin/sh`, `SKEL`, `USRSKEL=/usr/etc/skel`),
  умолчания `login.defs` (`UID_MIN/MAX`, `HOME_MODE 0750`, `USERGROUPS_ENAB`),
  создание `ossec-demo1` одной командой `useradd -m` (UID/GID 1001, UPG, дом `0750`,
  skel, поле пароля `!`), создание группы `ossec-proj` (GID 1002). Сценарий —
  `demos/07-user-defaults.sh`.
- `08-change-defaults.txt` — демо 08 (тот же образ). Две секции: «до» — `ossec-demo1`
  на стоковых умолчаниях (оболочка `/bin/sh`, дом `0750`); «после» —
  `useradd -D -s /bin/bash -f 30` и `HOME_MODE 0700` в `login.defs`, затем
  `ossec-demo2` той же командой `useradd -m` (оболочка `/bin/bash`, дом `0700`,
  поле `inactive` в `shadow` = 30). Сценарий — `demos/08-change-defaults.sh`.
- `09-environment-files.txt` — демо 09 (тот же образ; пользователь `ossec-demo1`
  с оболочкой `/bin/bash`). Секции: системные файлы (`/etc/environment` читает
  `pam_env`, `/etc/profile` перебирает `/etc/profile.d/*.sh`); «кто какой файл
  читает» (маркеры в `~/.profile`/`~/.bashrc`/скрипте `profile.d`: `bash -l` печатает
  profile.d и `~/.profile`→`~/.bashrc`, `bash -i` — только `~/.bashrc`); две секции
  злоупотребления `~/.bashrc` — учебная полезная нагрузка (`touch` файла-маркера
  выполняется от имени владельца при запуске оболочки) и перехват `PATH` (троянский
  `id` из `~/.local/bin`, печатает баннер и вызывает настоящий `id`). Полезные
  нагрузки намеренно безвредны. Сценарий — `demos/09-environment-files.sh`.

- `10-enum-accounts.txt` — демо 10 (раздел 5; одноразовый контейнер
  `ubuntu:26.04`, 29.10.2026, корневой сеанс; пользователи как в 15–17:
  `bob` 1001 (+`project`), `carol` 1002, `alice` 1003 (+`adm`, `project`),
  группа `project` GID 1010; установлены `gcc`, `libcrypt-dev`). Секции:
  сборка и запуск `10-enum-accounts.c`; таблица пользователей (вывод
  `getpwent`, полностью; длинный список вторичных групп `ubuntu` сокращён
  `…`); таблица групп (вывод `getgrent`; неинтересные системные группы
  вырезаны, пропуски отмечены строками `…`). Сценарий —
  `demos/10-enum-accounts.sh`.
- `11-password-auth.txt` — демо 11 (тот же контейнер). Секции: сборка
  (`gcc … -lcrypt`, установка в `/usr/local/bin/pwcheck`); корневой сеанс —
  верный пароль `bob` (`Lab-Demo-42!`, успех, UID из записи), неверный пароль
  (Access denied), несуществующее имя (отказ `getpwnam`); сеанс `bob` —
  `getspnam` возвращает `EACCES` (права `640 root:shadow`). Пароль при вводе
  не отображается (`getpass`); что вводилось — помечено комментарием к команде.
  Сценарий — `demos/11-password-auth.sh`.

- `12-nss-hosts.txt` — демо 12 (раздел 6, NSS; одноразовый контейнер
  `ubuntu:26.04`, 29.10.2026, дополнительно установлены `slapd`, `ldap-utils`,
  `sssd`, `libnss-sss` — поэтому в списке модулей есть `libnss_sss.so.2`, —
  а также `binutils` (objdump) и `strace`; локальный пользователь `bob` 1001).
  Секции: модули NSS (`ls`, `dpkg -S`, экспортируемые `_nss_sss_*`);
  конфигурация по умолчанию (**снята в чистом контейнере до установки sssd** —
  совпадает с заводской Ubuntu Server 26.04); имя в `/etc/hosts`
  (`192.0.2.80 intranet.example.test`, TEST-NET-1); имя только в DNS
  (`example.org`, адреса из реального DNS на момент записи); имени нет нигде;
  файловый источник недоступен (`chmod 000 /etc/hosts`, запросы от `bob`,
  `strace` ловит EACCES). Сценарий — `demos/12-nss-hosts.sh`.
- `13-nss-sssd.txt` — демо 13 (тот же контейнер): slapd с суффиксом
  `dc=example,dc=test`, в каталоге posixAccount `dave` (uid/gid 5000) и
  posixGroup `developers` (gid 5100, memberUid dave); sssd 2.12
  (`id_provider = ldap`, без TLS — лабораторное упрощение; пакет sssd сам
  дописал `sss` в nsswitch.conf). Секции: каталог LDAP (`ldapsearch`);
  подключение sss (`sssd.conf` дословно + строки nsswitch); файлы или каталог
  (`getent`/`getent -s`/`id`); ловушка `[!UNAVAIL=return]` (root/bob пропадают,
  возвращаются после `pkill sssd`); объединение групп `[SUCCESS=merge]`
  (локальная `developers:x:5100:bob` заведена при `group: files`, иначе
  `groupadd` видит каталожную группу и отказывает); кеш sss в действии
  (ответ из `/var/lib/sss/mc` при остановленном демоне; очистка файлов кеша —
  учебный приём, штатно `sss_cache -E`). Пароль администратора LDAP —
  публичный `LabLDAP-42!`. Сценарий — `demos/13-nss-sssd.sh`.

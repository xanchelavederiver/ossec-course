# Захваченные выводы (captures)

Курируемые транскрипты терминальных сессий для слайдов лекции 4 (механизмы
разграничения доступа); показываются компонентом `TerminalCapture`
(секции разделены строками `===== Заголовок =====`).

**17.11.2026 все транскрипты перезаписаны на эталонной ВМ** – Ubuntu Server
26.04.1 LTS, установленной с ISO (`project/scripts/vm/`, чистый оверлей), а не
в контейнере. Команды прежние; каждая команда транскрипта воспроизведена
сценарием, вывод сверен построчно. Состояние стенда: hostname `srv` (в
`/etc/hosts` – адрес самой ВМ), пользователи `bob` (UID 1001, группы `sudo`,
`users`, sudo без пароля – в транскриптах `$`-prompt), `carol` (1002),
`alice` (1003), `dave` (1004); в транскрипте 14 создаётся `johnny` (1005,
член групп alice/carol/dave). Установлены `gcc`, `acl`, `attr`
(на сервере по умолчанию их нет). Три настройки стенда, отличающие `bob` от
«заводского» пользователя сервера:

- `chmod 0755 /home/bob` – по умолчанию домашние каталоги создаются `0750`
  (`HOME_MODE`), и другие пользователи (carol, alice, johnny) не смогли бы
  запускать программы из `~bob/demoNN` (`sudo: './userinfo': command not found`);
- `umask 022` в `~bob/.profile` – login-сеанс Ubuntu Server получает `002`
  (`pam_umask` + личные группы); классическое `022` оставлено, чтобы права в
  примерах соответствовали тексту слайдов (см. слайд раздела 2.6);
- сеансы `bob` – login-оболочка с `PATH` из `/etc/environment` (как при входе
  по ssh; `getcap`/`setcap` лежат в `/usr/sbin`).

Отличия сервера от контейнера, попавшие в транскрипты:

- `/tmp` – **tmpfs** (`nosuid,nodev`): размеры каталогов 40/60 вместо 4096
  (05, 10, 16), в `lsattr` нет формат-атрибута `e`, `chattr =e` не
  поддерживается – в 10 атрибут снимается `chattr -i`; `chattr +a/+i` и ACL
  на tmpfs работают;
- список setuid-программ `/usr/bin` длиннее (`fusermount3`, `newgrp`,
  `ntfs-3g`) и идёт в другом порядке (03); порядок файлов в `lsattr` иной (08);
- в `auth.log` после ssh-сеанса последние строки – `sshd-session` и
  `systemd-logind` (09); вход по ssh записан через `script`, строки `spawn`
  от expect больше нет;
- loop-устройство – `/dev/loop3` (loop0–2 заняты snap-пакетами) (11);
- `07-inodes.txt` снят на той же ВМ (1,3 млн inode, занято ~150 тыс.), а не
  на рабочей машине.

Фрагменты кода ядра на слайдах – не captures, а листинги из github (v6.18).

Курирование: табуляция развёрнута (`expand -t 8`), хвостовые пробелы сняты,
префикс ошибок bash-редиректов приведён к интерактивному виду (`bash: …`),
прогресс-строки `mkfs.ext2` (CR-перерисовка) свёрнуты до итоговых `… done`.
Остальной вывод – дословный.

- `01-file-perms.txt` – права файлов: ELF исполняется без `r` (копия
  сохраняет имя `ls` – coreutils 26.04 multi-call), скрипту нужны `r`+`x`,
  шебанг.
- `02-dir-perms.txt` – каталоги: `r` без `x` (знаки `?`), `x` без `r`,
  `w` только с `x`.
- `03-setuid.txt` – setuid-root в /usr/bin; `userinfo` (assets/src);
  буква `S`; setuid на скрипте игнорируется.
- `04-setgid.txt` – `groupinfo`; setgid-каталог: наследование группы.
- `05-sticky.txt` – удаление чужого файла: свой каталог vs `/tmp` c `t`.
- `06-umask.txt` – umask 022/077 при создании файлов и каталогов.
- `07-inodes.txt` – `df --inodes /` (мотивация хранения прав в inode).
- `08-chattr-immutable.txt` – `+i` на /etc/pam.d/common-*: отказ root;
  тестовые строки «# edited …» после записи удалены из файлов.
- `09-chattr-append.txt` – `+a` на /var/log/auth.log: ssh-вход дописывает,
  root не может усечь/удалить; след `hehehe` затем удалён, rsyslog перезапущен.
- `10-chattr-dir.txt` – `a`/`i` на каталоге /tmp/experiments.
- `11-secure-delete.txt` – ext2 на loop: `+s` не перезаписывает блок
  (debugfs/dd – чтение устройства в обход ФС).
- `12-xattr.txt` – пространства имён user/trusted/security; setcap и
  `security.capability`.
- `13-acl-basics.txt` – минимальный vs расширенный ACL;
  `system.posix_acl_access`.
- `14-acl-algorithm.txt` – алгоритм проверки: владелец, именованный
  пользователь, группы, johnny (права из разных записей), `file_reader`
  (O_RDWR требует rw в одной записи).
- `15-acl-mask.txt` – chmod↔маска, `#effective`, маска в выводе `ls`.
- `16-acl-default.txt` – default ACL: наследование, umask не используется,
  независимость списков, `system.posix_acl_default`.

Курирование для ширины терминала (17.11.2026): в `09-chattr-append.txt` метки времени
`auth.log` сокращены до `ЧЧ:ММ:СС`; в `13-acl-basics.txt` значение
`system.posix_acl_access` сокращено многоточием; в `11-secure-delete.txt` длинная команда
`OFFSET=$(…)` перенесена на вторую строку через `\`.

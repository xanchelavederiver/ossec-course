# Захваченные выводы (captures)

Курируемые транскрипты терминальных сессий для слайдов лекции 5
(разграничение ресурсов); показываются компонентом `TerminalCapture`
(секции разделены строками `===== Заголовок =====`).

Транскрипты **перезаписаны 17.11.2026 на эталонной ВМ** – Ubuntu Server
26.04.1 LTS, установленной с ISO (`project/scripts/vm/`, чистый оверлей;
2 vCPU, 2 ГБ, ядро 7.0.0-43, hostname `srv`), а не в привилегированном
контейнере `ubuntu:26.04`, как при первой записи (26.10.2026). Иерархией
`cgroup2` управляет `systemd`: в корне включены `cpu memory pids`
(`cgroup.subtree_control`), оболочка пользователя живёт в
`user.slice/user-1001.slice/session-N.scope`.
Пользователи: `bob` (UID 1001, sudo без пароля – в транскриптах `$`-prompt,
вход по ssh), `x` (UID 1002, пароль `res12345`, для демонстрации `pam_limits`
по ssh: `bob` выполняет `ssh x@srv` к штатному `sshd`).

Сеансы записаны как настоящие интерактивные входы по ssh (по одному входу
на секцию `ulimit`), поэтому сообщения оболочки имеют вид `-bash: …`, а
завершённые сигналом задания печатаются в интерактивном формате
(`File size limit exceeded   (core dumped) dd …`, `Killed   python3 …`).

Курирование: табуляция развёрнута (`expand -t 8`), хвостовые пробелы сняты,
приглашение `bob@srv:~$` сведено к `$`, листинг `ls` сведён к трём колонкам,
служебные строки подготовки иерархии и уведомления оболочки о завершении
фоновых заданий (`[1]+ Done …`, `Terminated`) убраны, информационные строки
`stress-ng: info:` убраны, у `pidstat` оставлен итоговый блок `Average:`,
бесконечный поток `fork: retry` форк-бомбы оборван многоточием (`…`).
`PID` – фактические. Остальной вывод – дословный.

Отличия сервера от контейнера, учтённые на слайдах: `max user processes`
и `pending signals` = 6283 (в контейнере – `unlimited`/128218), `core file
size` = 0; `tee`/`ls` – из `rust-coreutils` (uutils 0.10.0), поэтому отказ
`tee` печатается как `<файл>: No such file or directory (os error 2)`;
`cgroup.stat` содержит ещё счётчики по подсистемам (на слайде – `grep
descendants`); в группе появились файлы `cgroup.stat.local` и
`pids.events.local`; после переноса оболочки в группе сессии остаются
процессы `sshd`; на двух ядрах три процесса в `R` делят 25 % неравномерно
(6/13/6 %); опция монтирования `memory_hugetlb_accounting`.

- `01-ulimit-basics.txt` – `ulimit -a`; мягкий (`-S`) и жёсткий (`-H`)
  лимиты числа открытых файлов, правило «понижать – можно, повышать –
  привилегия».
- `02-ulimit-examples.txt` – пять сценариев исчерпания: дескрипторы (`-n`),
  форк-бомба (`-u`), размер файла (`-f`), виртуальная память (`-v`),
  процессорное время (`-t`).
- `03-pam-limits.txt` – постоянный жёсткий `fsize` 1024 КБ в `limits.conf`,
  применённый при входе по ssh; файл 32 КБ проходит, 2 МБ – `File too large`.
- `04-cgroup-basics.txt` – создание группы и её интерфейсные файлы (50 файлов); перенос
  процесса записью `PID` в `cgroup.procs`; лимит `pids.max`; удаление.
- `05-cgroup-controllers.txt` – `cgroup.controllers` vs `cgroup.subtree_control`;
  ограничение сверху вниз; поле `populated` в `cgroup.events`.
- `06-cgroup-cpu-quota.txt` – квоты `cpu.max` по иерархии `A → {P,Q,R}`;
  измерение `pidstat`: 10/15/25 % по процессу; три процесса делят 25 % группы
  (6/13/6 %); `stress-ng` запущен с `--temp-path /tmp`, так как текущий каталог –
  `cgroupfs`.
- `07-cgroup-version.txt` – проверка версии: единственная иерархия типа
  `cgroup2`.

> Координаты выносок (`TCallout`) привязаны к 1-based строкам и столбцам
> секций этих файлов (после отсечения пустых строк) и проверены скриптом;
> при пересъёмке демонстраций их нужно пересчитать.

# Демонстрации лекции 5

Нумерованные сценарии воспроизводят демонстрации слайдов (номера совпадают с
файлами в `../captures/`). Запуск — **только в одноразовой ВМ** Ubuntu Server
26.04 или в привилегированном контейнере `ubuntu:26.04` с делегированным
`cgroup2`:

```console
sudo env OSSEC_DEMO_VM=1 bash 04-cgroup-basics.sh
```

Каждый сценарий сам создаёт одноразовых пользователей (`ossec-bob`,
`ossec-x`) и удаляет их при завершении; изменяемые системные файлы
резервируются (`backup_file`/`restore_files` в `lib/common.sh`) и
восстанавливаются даже при ошибке посередине. Группы управления создаются
под `/sys/fs/cgroup/ossec-demo` и удаляются на выходе (`cg_cleanup`).
Ожидаемые отказы (`EPERM`, `EMFILE`, `SIGXFSZ`, `Device or resource busy`) —
часть демонстраций: сценарий продолжает работу.

Требования: базовая система + `python3`, `stress-ng`, `sysstat` (`pidstat`),
`procps` (`pgrep`), `openssh-server` и `expect` (для демо 03). Для демонстраций
cgroup необходим смонтированный `cgroup2` с доступными контроллерами `cpu`,
`memory`, `pids` (проверяется в начале сценария).

| Сценарий | Слайды | Что показывает |
|---|---|---|
| `01-ulimit-basics.sh` | раздел 2.2–2.3 | `ulimit -a`; мягкий и жёсткий лимиты |
| `02-ulimit-examples.sh` | раздел 2.4 | nofile, nproc (fork bomb), fsize, as, cpu |
| `03-pam-limits.sh` | раздел 2.4 | постоянный `fsize` через `pam_limits` при входе по ssh |
| `04-cgroup-basics.sh` | раздел 3.3 | создание группы, `cgroup.procs`, `pids.max`, `rmdir` |
| `05-cgroup-controllers.sh` | раздел 3.4 | `subtree_control`, ограничение сверху вниз, `cgroup.events` |
| `06-cgroup-cpu-quota.sh` | раздел 3.6 | квотирование CPU по иерархии `A → {P,Q,R}` |

> Транскрипты в `../captures/` курированы (развёрнуты табуляции, выровнены
> `PID`, убраны служебные строки); координаты выносок на слайдах
> привязаны к этим файлам и при пересъёмке демонстраций требуют пересчёта.
